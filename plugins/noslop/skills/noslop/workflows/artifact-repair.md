# Artifact repair — Level 2 workflow (R07)

Start from the reader's job, intended format, original material facts and actual defects—not from a requirement to redesign everything.

1. Read [Slop signs](../references/slop-signs.md) to diagnose real defects, including usability, accuracy, accessibility, visual hierarchy and functionality.
2. State in one sentence what the reader must understand or do. Identify whether the existing output format is explicitly requested or must be changed by the user.
3. **Choose proportionately:** repair specific faulty parts when the rest works; rebuild when the artifact has foundational failures, the wrong form for its reader, pervasive defects, or unsafe/unmaintainable structure. A similar-looking but corrected result can be entirely valid.
4. Read [Content integrity](../references/content-integrity.md). Preserve material facts, numbers, reasons, exceptions, original constraints, and functioning controls. Do not invent missing facts.
5. **No mandatory ~50% text cut.** Cut peripheral duplication and noise only when it helps the reader. Material correctness takes priority.
6. Read the appropriate form-specific Level 2 workflow and [Design rules](../references/design-rules.md) for layout. For HTML, load [Style kit](../references/style-kit.md); for other requested formats use the relevant production capabilities.
7. Before delivery, load [Quality checks](../references/quality-checks.md), compare against the original, and report the material fixes and any unresolved limitation concisely.

Strict R03 layout caps and R04 first-screen range remain in force. If they conflict with necessary information, ask rather than silently omit it. Never deploy a repaired artifact without explicit publication authorization (R08).
